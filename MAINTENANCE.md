## 1. Что это за проект

**AI-Rabotnik** — одностраничный PWA-сайт (лендинг) агентства по разработке
цифровых ИИ-работников. Чистый статический HTML/CSS/JS, **без сборщика и
бэкенда**. Вся логика интерактива реализована в одном файле `app.js`.

Ключевые особенности:
- SEO/LLM-готовность: семантическая вёрстка, Open Graph, Twitter Card,
  JSON-LD (Organization, ProfessionalService, FAQPage — **без фейкового рейтинга**).
- PWA: `manifest.json` + service worker `sw.js` (offline-first для статики).
- Аналитика: Google Analytics 4 + Яндекс.Метрика — **загружаются только при
  задании реальных ID** (плейсхолдеры `G-XXXXXXXXXX` / `0` = выключено, не шлют
  «битых» запросов).
- Форма захвата заявок (`leadForm`) с валидацией, буфером в `localStorage`
  и опциональной отправкой через Formspree или свой backend.
- Юридические страницы: `privacy.html` (152-ФЗ), `offer.html` (договор-оферта).
- Docker-деплой через `nginx:1.27-alpine` (`Dockerfile`, `docker-compose.yml`,
  `nginx.conf`).

### Источник правды — исходные файлы

`index.html` подключает **`styles.css`** и **`app.js`** напрямую (без
минификации). Это сделано намеренно: в окружении нет `terser`/`csso` и
`python3`, поэтому сборка `.min`-версий была невозможна и создавала риск
рассинхрона (правишь `app.js` — на сайте ничего не меняется). Сжатие
отдаёт nginx через `gzip` (см. `nginx.conf`), так что вес при передаче
не страдает.

- Править контент/разметку — в `index.html` напрямую.
- Править стили — в `styles.css`; JS-логику — в `app.js`. Никакой пересборки не нужно.
- Если когда-нибудь вернёте минификацию — не забудьте пересобрать `.min` и
  вернуть ссылки в `index.html`, а в `sw.js` обновить `ASSETS` и версию кэша.

| Слой | Технология |
|---|---|
| Разметка | Семантический HTML5 |

**Нет** в проекте: npm-зависимостей, package.json, шагов сборки, тестов,
CI. Это сознательный выбор ради простоты — учитывайте при развитии.

## 4. Локальный запуск (разработка)

### Вариант А — просто статикой
```bash
cd ai-rabotnik
python3 -m http.server 8000
# открыть http://localhost:8000
```
Недостаток: service worker и fetch к API могут вести себя иначе, чем в проде.
Для проверки PWA нужен вариант Б.

### Вариант Б — через nginx (ближе к проду)
```bash
docker compose up --build
# открыть http://localhost:8080
```
Порт меняется переменной `PORT`: `PORT=3000 docker compose up`.

## 5. Деплой

### Docker (универсально)
```bash
docker compose up -d --build
```
Образ: `ai-rabotnik:latest`, контейнер `ai-rabotnik`, авто-рестарт
`unless-stopped`, healthcheck через `wget`.

### Статика (Netlify/Vercel/GH Pages/Cloudflare)
Залейте содержимое папки `ai-rabotnik/` как статический сайт.
Для PWA **обязателен HTTPS** (браузеры не регистрируют SW по HTTP, кроме localhost).

`nginx.conf` уже настраивает: gzip, кэш статики на 30 дней (`immutable`),
отсутствие кэша для `sw.js` и `manifest.json`, security-заголовки
(`X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `X-XSS-Protection`),
отдачу кастомного `404.html`.

## 7. Руководство по поддержке (рутинные правки)

### 7.1 Правка стилей и JS
Поскольку сайт грузит исходники напрямую (см. раздел 2), никакой
минификации/пересборки не требуется: правите `styles.css` / `app.js` —
изменения сразу видны. Сжатие при отдаче обеспечивает nginx (`gzip` в
`nginx.conf`).

### 7.2 Настройка аналитики (опционально)
Аналитика **выключена по умолчанию** и не мешает запуску. Чтобы включить:
в `index.html` в блоке аналитики задайте реальные ID:
- `window.GA_ID = 'G-XXXXXXXXXX';` → заменить на ваш GA4 Measurement ID
  (формат `G-` + 10 символов A–Z0–9, напр. `G-AB1CD2EF3G`). Скрипт GA
  подгрузится автоматически **только** при совпадении с этим форматом и при
  отличии от плейсхолдера (защита от случайного «битого» ID).
- `window.YM_ID = 0;` → заменить на числовой ID Яндекс.Метрики.
Пока стоят плейсхолдеры — скрипты не загружаются и не шлют «битых» запросов.

В `app.js` (строки 98–100) настроить отправку формы — см. раздел 8.2.

### 7.3 Обновление даты в sitemap
`sitemap.xml` содержит `<lastmod>2026-08-24</lastmod>`. Обновляйте при
каждом значимом изменении контента (влияет на переиндексацию).

### 7.4 Иконки PWA
При смене бренда обновите `assets/icons/*` (192/512/maskable) и `favicon.svg/.ico`.
Имена файлов зафиксированы в `manifest.json` и `index.html` (строки 34–37).

## 8. Руководство по развитию (новые фичи)

### 8.1 Добавить новую секцию на главную
1. Скопируйте блок нужной секции в `index.html` (используйте существующие
   классы `.container`, `.section-title`, `.card-title`).
2. Присвойте уникальный `id` и добавьте ссылку в навигацию/футер.
3. Стили — в `styles.css`, затем пересобрать `styles.min.css` (раздел 7.1).

### 8.2 Подключить реальную отправку формы
В `app.js` (строки 98–100) задать один из endpoint'ов:
```js
var FORMSPREE_ID = "xaybnvqp";          // Formspree (без сервера)
// ИЛИ
var OWN_API = "/api/lead";               // свой backend (POST JSON)
```
Если оба пусты — данные только пишутся в `localStorage` (режим демо).
Для своего backend: в `nginx.conf` добавить `location /api/lead { proxy_pass … }`.

### 8.3 Новый язык / локализация
Сайт только на `ru` (`lang="ru"`, `og:locale="ru_RU"`). Для i18n потребуется
либо отдельная страница (`/en`), либо JS-роутер — в текущей архитектуре
заложено не было.

### 8.4 Добавить страницу в PWA/offline-кэш
В `sw.js` (массив `ASSETS`, строки 7–15) добавить путь к новому файлу,
**и поднять версию кэша** `CACHE = "ai-rabotnik-v2"` → `v3`, иначе браузер
продолжит отдавать старый кэш.

### 8.5 Деплой новой версии в Docker
```bash
docker compose build --no-cache && docker compose up -d
```
Healthcheck проверит доступность `/`.

## 10. Известные ограничения и TODO

- **Нет сборщика/зависимостей** — сайт грузит исходники напрямую; минификация
  не используется (сжатие отдаёт nginx через gzip). Это устраняет былую
  проблему рассинхрона `.min`-файлов.
- **Аналитика отключена по умолчанию** — пока `GA_ID`/`YM_ID` стоят
  плейсхолдерами, скрипты не грузятся (не мешают запуску). Включается заданием
  реальных ID (раздел 7.2).
- **Форма в демо-режиме** — без `FORMSPREE_ID`/`OWN_API` заявки пишутся только
  в `localStorage` браузера и не доходят до владельца. Сообщение об этом теперь
  явное (не «успех»). Настройка — раздел 8.2.
- **Нет тестов, CI, линтера** — качество правок контролируется вручную.
- **assets/img/og-cover.png** должен существовать (используется в OG) —
  проверьте наличие файла перед деплоем.
- `architecture-diagram.html` лежит в корне, но не связан с сайтом — это
  вспомогательная схема, можно вынести в `docs/`.

## 12. История исправлений

### 2026-08-24 — Устранение ошибок запуска (без сети)
Выполнено по методологии systematic-debugging + независимый code-review.

1. **Root-cause: ловушка `.min`-файлов.** Сайт грузил `styles.min.css` /
   `app.min.js`, которые в офлайн-окружении нечем пересобрать (нет `terser`/
   `csso`, `python3`, `npx` падает без сети). Риск рассинхрона устранён:
   `index.html` теперь грузит `styles.css` / `app.js` напрямую, `.min`-файлы
   удалены, `sw.js` и `architecture-diagram.html` приведены в соответствие.
2. **Битый запрос GA при каждом запуске.** Невалидный `G-XXXXXXXXXX`
   инжектировался как live-скрипт. Переписан загрузчик аналитики: скрипты
   подгружаются только при реальных ID (`gaReady` для GA — явная проверка
   плейсхолдера + regex-формат `G-[A-Z0-9]{10}`; `YM_ID !== 0` для Метрики).
3. **Фейковый рейтинг в JSON-LD.** Удалён `aggregateRating: 4.9 / 37` из
   `ProfessionalService` (риск санкций поисковиков за фейковые отзывы).
3b. **2026-08-24 (2) — Инвизибл-оверлей блокировал весь клик.**
   **Симптом:** при локальном запуске не работали вообще все интерактивные
   элементы — навигационные якоря (`#services` и т.п.), бургер-меню, CTA-кнопка
   «Оставить заявку», карточки услуг. Root cause (предшествующий баг):
   `.modal-overlay` имел `position: fixed; inset: 0; z-index: 1000;
   display: flex` — атрибут `hidden` должен был скрывать его через браузерное
   `[hidden]{display:none}`, но авторский `display:flex` **перебивал** это.
   Итог: модалка невидима (`opacity:0`), но постоянно перекрывала весь вьюпорт
   и перехватывала все клики. Аналогичный дефект у `.mobile-nav` в мобильном
   медиа-запросе (`display:flex` без guard на `hidden`).
   **Фикс:** добавлены `.modal-overlay[hidden]{display:none}` и
   `.mobile-nav[hidden]{display:none}` (специфичность выше базы, без
   `!important`). Теперь `hidden` реально исключает элемент из hit-testing.
   Проверено расчётом каскада по реальному отданному CSS.
4. **Вводящая в заблуждение форма.** Сообщение демо-режима теперь явно говорит,
   что заявка сохранена только локально и нужен `FORMSPREE_ID`/`OWN_API`.
5. Служебное: `sitemap.xml` `<lastmod>` → `2026-08-24`; версия кэша SW
   `ai-rabotnik-v2` → `v3`.
6. **2026-08-24 (3) — Удалены маркеры ИИ-генерации + адаптивная навигация.**
   **Удалено (AI-tells):** декоративный `hero-badge` (пульсирующая пилюля,
   дублирующая H1) и секция `trust-bar` со строкой брендов
   (OpenAI/Anthropic/YandexGPT/…) — типичный шаблонный «неросетевой» наполнитель
   без верифицируемой информации. Мёртвые CSS-правила и `@keyframes pulse`
   удалены. **Адаптив (best practices):** перестроен блок RESPONSIVE — на десктопе
   явно заданы дефолты (`.main-nav` flex, `.burger` none, `.mobile-nav` none),
   поэтому бургер **никогда не показывается на десктопе**; при `≤900px` навигация
   переключается на бургер + выпадающее меню. Добавлены: тач-цели ≥44px,
   анимация бургер→крестик по `aria-expanded`, закрытие меню по клику вне/`Escape`.
   Проверено расчётом каскада (DESKTOP burger=none/main-nav=flex; MOBILE
   burger=flex/main-nav=none/mobile-nav=flex → NAV_RESPONSIVE_OK).
   **Доступность (доп. раунд):** по независимому ревью добавлены Escape-закрытие
   мобильного меню (с приоритетом над модалкой), фокус на первой ссылке при
   открытии и возврат фокуса на бургер при закрытии (AT-пользователи).

**Проверка (tight feedback loop, green):** все локальные ассеты в `index.html`
существуют (0 missing); 3 JSON-LD-блока валидны; аналитика защищена гвардом;
статический security-скан чист (нет секретов/eval/XSS). Независимый ревьюер:
_результат см. в чате_.

**Что осталось плейсхолдерами (не блокирует запуск, требует ввода владельца):**
реальный домен вместо `ai-rabotnik.ru`, контакты/реквизиты в футере и JSON-LD,
реальные `GA_ID`/`YM_ID` (опционально), и настройка доставки формы
(`FORMSPREE_ID`/`OWN_API`).
